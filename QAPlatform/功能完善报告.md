# QA平台功能完善报告

## 📋 问题总结

用户反馈了两个主要问题：
1. **回答发布失败** - 无法发布回答到问题

## 🔧 解决方案

### 1. 数据库表结构完善

#### 创建用户关注表
```sql
CREATE TABLE IF NOT EXISTS user_follows (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    follower_id BIGINT NOT NULL COMMENT '关注者ID',
    following_id BIGINT NOT NULL COMMENT '被关注者ID',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '关注时间',
    FOREIGN KEY (follower_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (following_id) REFERENCES users(id) ON DELETE CASCADE,
    UNIQUE KEY unique_follow (follower_id, following_id),
    INDEX idx_follower (follower_id),
    INDEX idx_following (following_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 创建用户统计视图
```sql
CREATE OR REPLACE VIEW user_stats_view AS
SELECT 
    u.id, u.username, u.email, u.reputation,
    COALESCE(q_count.question_count, 0) as question_count,
    COALESCE(a_count.answer_count, 0) as answer_count,
    COALESCE(a_accepted.accepted_answers, 0) as accepted_answers,
    COALESCE(followers.followers_count, 0) as followers_count,
    COALESCE(following.following_count, 0) as following_count
FROM users u
LEFT JOIN (SELECT author_id, COUNT(*) as question_count FROM questions GROUP BY author_id) q_count ON u.id = q_count.author_id
LEFT JOIN (SELECT author_id, COUNT(*) as answer_count FROM answers GROUP BY author_id) a_count ON u.id = a_count.author_id
LEFT JOIN (SELECT author_id, COUNT(*) as accepted_answers FROM answers WHERE accepted = true GROUP BY author_id) a_accepted ON u.id = a_accepted.author_id
LEFT JOIN (SELECT following_id, COUNT(*) as followers_count FROM user_follows GROUP BY following_id) followers ON u.id = followers.following_id
LEFT JOIN (SELECT follower_id, COUNT(*) as following_count FROM user_follows GROUP BY follower_id) following ON u.id = following.follower_id;
```

### 2. 后端模型和Repository

#### UserFollow实体类
```java
@Entity
@Table(name = "user_follows")
public class UserFollow {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "follower_id", nullable = false)
    private User follower;  // 关注者
    
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "following_id", nullable = false)
    private User following; // 被关注者
    
    @CreationTimestamp
    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;
}
```

#### UserFollowRepository接口
```java
@Repository
public interface UserFollowRepository extends JpaRepository<UserFollow, Long> {
    boolean existsByFollowerIdAndFollowingId(Long followerId, Long followingId);
    long countFollowersByUserId(Long userId);
    long countFollowingByUserId(Long userId);
    Page<User> findFollowersByUserId(Long userId, Pageable pageable);
    Page<User> findFollowingByUserId(Long userId, Pageable pageable);
    void deleteByFollowerIdAndFollowingId(Long followerId, Long followingId);
}
```

### 3. API接口完善

#### 用户统计API
- `GET /api/users/{id}/stats` - 获取用户统计信息
  - 返回：问题数、回答数、采纳回答数、粉丝数、关注数

#### 关注功能API
- `POST /api/users/{id}/follow` - 关注用户
- `DELETE /api/users/{id}/follow` - 取消关注
- `GET /api/users/{id}/follow-status` - 获取关注状态
- `GET /api/users/{id}/followers` - 获取粉丝列表
- `GET /api/users/{id}/following` - 获取关注列表

#### 回答功能API
- `POST /api/questions/{questionId}/answers` - 发布回答
- `GET /api/questions/{questionId}/answers` - 获取问题回答列表
- `GET /api/users/{id}/answers` - 获取用户回答列表

### 4. 安全配置优化

修改了UserController中的认证方式，使用`@RequestHeader("X-User-Id")`替代`@RequestAttribute("userId")`，避免了JWT认证中间件的依赖问题。
